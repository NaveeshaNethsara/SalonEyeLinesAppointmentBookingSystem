# Collapse Booking Allocation Seam

Previously, booking allocation logic was fragmented across three disparate locations: an orphaned `AppointmentBookingEngine` service, raw inline queries in `/api/appointments` route handlers, and client-side collision calculations in `/book`. We decided to collapse all booking logic into `BookingEngine` as the single authoritative deep module for creation, rescheduling, cancellation, slot availability calculation, and status reconciliation. The HTTP route handlers (`/api/appointments` and `/api/appointments/[id]`) and `/api/bookings/slots` were reduced to thin adapters delegating directly to `BookingEngine`. This guarantees transaction-safe row-level locking, 5-minute buffer enforcement, multi-treatment contiguity, and status reconciliation across all entry points with 100% backwards compatibility for existing frontend clients.
